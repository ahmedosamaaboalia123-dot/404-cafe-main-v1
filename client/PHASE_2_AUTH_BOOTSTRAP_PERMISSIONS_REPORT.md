# تقرير اكتمال المرحلة الثانية: الدخول والتهيئة والصلاحيات

## النطاق المنفذ

تم ربط دورة جلسة الإدارة بعقد `/api/v1` الفعلي من دون تعديل الباك إند. تشمل المرحلة تسجيل الدخول، اعتماد الجهاز، حفظ التوكنات، استعادة الجلسة من bootstrap، تحديث التوكن، تسجيل الخروج، حماية المسارات، وإظهار عناصر السايدبار طبقًا لصلاحيات الخادم.

## عقد تسجيل الدخول

- يرسل الفرونت `name` و`password` و`fingerprint` في المستوى الأعلى.
- ترسل معلومات الجهاز داخل `device` بالحقول `name` و`browser` و`os` فقط.
- تستعمل بصمة FingerprintJS الواحدة طوال جلسة الصفحة بدل تحميل المكتبة في كل محاولة.
- تقرأ حالة الجهاز المعلق من استجابة HTTP 202 ذات `status: DEVICE_APPROVAL_REQUIRED` وتعرض زرًا لإعادة التحقق بنفس بيانات المحاولة.
- تمر أخطاء الجهاز المحظور وباقي الأخطاء عبر الخطأ العربي الموحد في API core.
- تقرأ التوكنات بأسمائها الصحيحة: `accessToken` و`refreshToken`.

## دورة الجلسة

1. بعد نجاح الدخول تُحفظ التوكنات فقط في `localStorage`.
2. بيانات الموظف والدور والصلاحيات والإشعارات والحضور والوردية تبقى في Zustand.
3. عند إعادة فتح التطبيق يستدعي `GET /admin/bootstrap` لاستعادة الحالة المعتمدة من الخادم.
4. عند انتهاء access token ينفذ API core محاولة refresh واحدة مشتركة للطلبات المتزامنة ويحدّث التوكن في التخزين والحالة.
5. عند فشل refresh تُمسح الجلسة والطلبات المعلقة.
6. تسجيل الخروج يرسل `{ refreshToken, allSessions: false }` ثم ينظف الحالة المحلية ويفصل Socket.

## الصلاحيات

- حُوّل شكل الصلاحيات إلى `{ pageKey, visible, actions }` عند حد API.
- التحقق يدعم صلاحية الصفحة مثل `orders` وصلاحية الفعل مثل `orders.create` والمفاتيح المركبة مثل `employees.password.view`.
- أزيل تجاوز الحماية بناءً على اسم الدور؛ الخادم هو مصدر الحقيقة لكل الأدوار.
- جرى تصحيح مفاتيح المسارات، ومنها `purchase-returns` و`reports` و`tables` و`preparation` و`table-services`.
- أصبحت صفحات البيع وتفاصيل الطلب التي كانت بلا حماية مغطاة بـ ProtectedRoute.
- أضيف سجل تنقل ثابت في الفرونت لربط مفاتيح الباك بالأسماء العربية والمسارات والأيقونات، لأن bootstrap لا يرسل أسماء العرض أو المسارات.

## توحيد البيانات

- الإشعارات موحدة إلى `{ unreadCount, items }`.
- حالة الجلسة تضم `currentAttendance` و`shift` و`featureFlags` و`realtime`.
- يوجد adapter يقبل الشكل القديم عند الحد فقط حتى لا تنتشر أسماء snake_case داخل المكونات.
- لم يعد `auth_session` يُنشأ أو يُعتمد عليه.

## التحقق

- اختبارات auth الجديدة تغطي adapters، الجهاز المعلق، الإشعارات، صلاحيات الصفحة والفعل، الصفحات المخفية، any/all، وسجل التنقل.
- إجمالي الاختبارات بعد المرحلة: 27 اختبارًا.
- لا تعتمد المرحلة على Chromium أو Playwright.
