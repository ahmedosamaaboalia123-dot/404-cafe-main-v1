# تقرير إتمام المرحلة 12 — العميل الأونلاين والتيك أواي والباريستا الذكي

## الطلب والدفع

- إنشاء الطلب يعمل على `POST /api/v1/public-orders` فقط.
- النوعان هما `TAKEAWAY` و`DELIVERY`، والدفع كاش وفق عقد النظام.
- التيك أواي يطلب الاسم والهاتف، والتوصيل يطلب الاسم والهاتف والعنوان.
- عناصر الطلب ترسل MongoDB ids كنصوص من دون تحويل رقمي.
- كل محاولة checkout تحمل Idempotency-Key ثابتًا حتى النجاح.

## التخزين المحلي

- يخزن آخر بيانات الاسم والهاتف والعنوان وحقول العنوان لإعادة الملء التلقائي.
- يخزن لكل طلب: رقم الطلب، الباركود، read token، action token، وتواريخ انتهائها.
- لا يخزن الأصناف أو الحالة أو الإجماليات كمصدر حقيقة.
- طلب جديد يحدث آخر profile، وإضافة أصناف لطلب قائم لا تحدثه.

## الوصول والتاريخ

- ينشئ CustomerAccessSession من رقم الطلب وaction token.
- سجل «طلباتي» يأتي من الخادم بحد 10 بدل قائمة الطلبات المحلية القديمة.
- lookup برقم الطلب والهاتف يعرض الإسقاط الآمن.
- إذا كان read token محفوظًا على الجهاز تنتقل الواجهة بعد lookup إلى التتبع الكامل.
- لا يدعي الفرونت إمكان استصدار token جديد من lookup لأن الباك لا يعيده.

## التتبع والعمليات

- التتبع يستخدم `X-Tracking-Read-Token`.
- الإضافة والإلغاء والاستلام والتقييم تستخدم `X-Order-Action-Token`.
- زر إضافة المنتجات يفتح المينيو مع رقم الطلب، ثم يضيفها إلى نفس الطلب.
- الإضافة لا تنشئ طلبًا جديدًا ولا تغير profile العميل.
- طلب الإلغاء يتطلب سببًا ويترك قرار التنفيذ للإدارة.
- زر الاستلام يظهر عند خروج طلب التوصيل للمندوب.
- التقييم يظهر بعد اكتمال أو تسليم الطلب.
- كل command يرسل expectedVersion المتاح من حالة التتبع ومفتاح idempotency.

## التزامن

- صفحة التتبع تستخدم قناة الطلب عند وجود token.
- بعد reconnect أو نجاح command تعيد REST sync من المصدر الحقيقي.
- الواجهة لا تعدل حالة المخزون أو الطلب محليًا كحقيقة نهائية.

## الباريستا الذكي

- endpoint المستخدم هو `/api/v1/customer-ai/chat`.
- السياق المرسل يقتصر على ids المنتجات الظاهرة وملخص السلة.
- لا ترسل الواجهة وصفات أو تكاليف أو أرصدة مخزون أو بيانات عميل إلى النموذج.
