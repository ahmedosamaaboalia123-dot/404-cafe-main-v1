# تقرير إتمام المرحلة 10 — الطلبات والتحضير والطاولات والفواتير

## المنفذ

- إنشاء طبقة API موحدة لكل عقود الإدارة الخاصة بالطلبات والتحضير والطاولات والجلسات والمدفوعات والفواتير وطلبات الإلغاء.
- تثبيت `limit=10` لكل القوائم، واستخدام React Query cache ومفاتيح استعلام مستقلة لتقليل الطلبات.
- الحفاظ على MongoDB ids كسلاسل وإزالة التحويل العددي من مسار البيع الجديد.
- تمرير `expectedVersion` للطلب والعنصر والطاولة والجلسة والدفع وطلبات الإلغاء لمنع الكتابة المتعارضة.
- استخدام Idempotency-Key ثابت طوال محاولة كل command ومنحه مفتاحًا جديدًا بعد النجاح.
- ربط إنشاء طلب أونلاين/تيك أواي وإنشاء جلسة طاولة وإضافة منتجات إلى جلسة قائمة بالعقود الفعلية.
- ربط التحضير بقائمتي current/ready ومجموعتي online/tables، وتجهيز الصنف وإلغاء الصنف أو الطلب مع سبب.
- ربط لوحة الطاولات بحالات EMPTY/OCCUPIED/OUT_OF_SERVICE، وصفحة الجلسة، والإغلاق النقدي والطباعة.
- ربط سجل الطلبات بجدولي online/tables والبحث والطباعة وserver pagination.
- إنشاء شاشة فواتير الطلبات مع البحث والطباعة وتسجيل حدث الطباعة.
- إنشاء شاشة طلبات الإلغاء مع القبول والرفض والسبب وserver pagination.
- إضافة روابط التحضير والسجل والفواتير والإلغاءات إلى الصفحة الرئيسية للطلبات.

## مسارات الواجهة

- `/admin/orders/online`
- `/admin/orders/takeaway`
- `/admin/orders/tables`
- `/admin/orders/tables/:tableId`
- `/admin/orders/sales/:type/:id`
- `/admin/orders/preparation`
- `/admin/orders/preparation/:orderId`
- `/admin/orders/history`
- `/admin/orders/cancellations`
- `/admin/invoices`

## الحماية من التكرار والتعارض

- كل mutation يرسل Idempotency-Key.
- كل انتقال حساس يرسل النسخة التي عرضها السيرفر.
- النجاح يبطل فقط مجموعات cache المرتبطة.
- الفشل يبقي المفتاح صالحًا لإعادة نفس المحاولة ويعرض رسالة الباك العربية.
- الخصم والإرجاع لا ينفذان في الفرونت؛ الباك ينفذهما داخل transaction ثم تعيد الواجهة المزامنة.
