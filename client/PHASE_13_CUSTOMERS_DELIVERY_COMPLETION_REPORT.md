# المرحلة 13 — العملاء والمناديب والتوصيل والكاش وواتساب

## المنفذ

- ربط شاشة العملاء بعقد `GET /customers-screen` مع البحث وPagination ثابت 10 عناصر.
- ربط إنشاء العميل وتفاصيله وتعديله بعقود الباك الحالية، مع `expectedVersion` و`Idempotency-Key`.
- عرض طلبات العميل وتقييماته، وإتاحة طباعة فاتورة كل طلب.
- ربط شاشة المناديب بعقد `GET /delegates-screen`، وعرض السعة والطلبات النشطة والمنتهية والعهدة النقدية.
- إسناد طلب التوصيل الجاهز لمندوب متاح مع منع اختيار مندوب وصل إلى أقصى سعة.
- تنفيذ دورة الإسناد: إسناد، تسليم للمندوب، نقل لمندوب آخر، تعذر التوصيل، عودة للمحل، وتأكيد التسليم إداريًا بسبب إلزامي.
- تنفيذ تسوية كاش الطلب المسلم؛ الباك هو المسؤول عن إنشاء حركة الدرج وربطها بالتسوية.
- إنشاء رابط WhatsApp من رقم المندوب وبيانات الفاتورة المطبوعة، وتسجيل حدث فتح المشاركة في الباك.
- إزالة حقول الواجهة القديمة غير المدعومة مثل حذف العميل، بريد العميل، نوع طلب ثابت للعميل، ورقم WhatsApp منفصل للمندوب.

## قواعد الاتساق

- التعيين لا يعني خروج الطلب للتوصيل؛ زر «تسليم للمندوب» ينفذ الانتقال المنفصل.
- كل mutation مالي أو تغيّر حالة يستخدم مفتاح تكرار ثابت أثناء إعادة المحاولة.
- كل تحديث متزامن يرسل نسخة السجل الحالية حتى يعيد الباك `409` عند التعارض.
- روابط السوشيال لا تُمسح عند تعديل عميل إذا لم يرجعها عقد التفاصيل.
- مشاركة WhatsApp تفتح محادثة جاهزة للمراجعة؛ الإرسال النهائي يظل بقرار المستخدم داخل WhatsApp.

## التحقق

- `npm run lint`: ناجح.
- `npm run test:run`: 20 ملف اختبار، 92 اختبارًا ناجحًا.
- `npm run build`: ناجح (تحذير حجم bundle قائم من المشروع ولا يمنع البناء).
- لا يعتمد التنفيذ على Chromium أو Playwright.
