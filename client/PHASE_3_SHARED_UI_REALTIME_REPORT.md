# تقرير اكتمال المرحلة الثالثة: المكونات المشتركة وReact Query وRealtime

## ما تم تنفيذه

أنشئت طبقة مشتركة تستخدمها الموديولات التالية أثناء ترحيلها، بدل تكرار حالات التحميل والجداول والطباعة والتعارض والاتصال اللحظي في كل شاشة.

### React Query

- `createQueryClient()` هو المصدر الموحد لإعداد QueryClient.
- أخطاء 400 و401 و403 و404 و409 و422 لا يعاد إرسالها تلقائيًا.
- أخطاء الشبكة و503 و5xx القابلة للمحاولة تعاد مرتين بحد أقصى مع backoff.
- توسعت query-key factories لتغطي الطلبات والتحضير والطاولات وخدماتها والحالات والمدفوعات والتوصيل والتقارير.
- debounce الافتراضي للبحث أصبح 500ms، ضمن نافذة نصف ثانية إلى ثانية المتفق عليها.

### المكونات المشتركة

- `ServerPagination`: يعتمد على meta الخادم، يثبت limit عند 10، ويوفر السابق والتالي والإجمالي مع أزرار لمس 44px.
- `AsyncState`: حالات Loading وEmpty وError وإعادة المحاولة، مع مكونات منفصلة قابلة لإعادة الاستخدام.
- `ConfirmAction`: يمنع الضغط المتكرر، ويدعم السبب الإلزامي، ويبقي النافذة مفتوحة إذا فشل command.
- `ConflictDialog`: يعرض تعارض النسخة ويوفر تحميل أحدث سجل أو إلغاء التعديلات المحلية.
- `PrintDocument`: لا يطبع بيانات قائمة عادية؛ يستطيع تحميل print-data المخصص، تجهيز المستند، الطباعة، ثم تسجيل حدث الطباعة.
- `Money` و`Quantity`: يعرضان decimal strings بصورة موحدة من دون تنفيذ قرارات مالية باستخدام Float.
- `DateTime`: يعرض التاريخ والوقت بالعربية ويتعامل مع القيمة غير الصالحة بأمان.

### Realtime

- Socket إداري singleton مع تحديث التوكن وإعادة الاتصال عند تغيره.
- اتصال scoped لكل شاشة مع إزالة listeners عند unmount أو remount.
- اشتراك صريح في الغرف حتى 20 غرفة كما يسمح الباك.
- استقبال envelope العام `event` المطابق للباك بدل افتراض أسماء أحداث منفصلة.
- منع الحدث المكرر عن طريق `eventId`، ورفض sequence القديم لكل aggregate بصورة مستقلة.
- اكتشاف sequence gap وتشغيل `/api/v1/realtime/sync` لاستعادة الأحداث الناقصة.
- تطبيق snapshots أثناء الاستعادة، مع حد أقصى لعشر صفحات حماية من loop غير منتهٍ.
- mapping مركزي من aggregate إلى React Query keys.
- تجميع invalidations المتكررة في نافذة قصيرة لمنع request storm.
- متابعة تغير access token بين tabs عن طريق storage event.
- دعم رؤوس REST sync للطلب والطاولة وجلسة العميل.

## ملاحظة عقد الباك الحالية

Socket transport الموجود في الباك يصادق employee access token فقط. لذلك اتصال الإدارة قابل للاستخدام الكامل الآن. Factories الخاصة بالعميل والطاولة موجودة وفق الهيكل المطلوب، وREST sync يدعم توكناتهما فعليًا، لكن الباك الحالي سيرفض اتصال Socket العام إلى أن يدعم public socket identity. لن يُعدّل الباك طبقًا لقيد المشروع؛ ستستخدم مراحل العميل والطاولة REST sync كمسار الاستعادة ومصدر الحقيقة، ولن تدعي الواجهة وجود اتصال Socket ناجح عند رفضه.

## الحالات المغطاة

- event مكرر أو قديم أو خارج الترتيب.
- وجود gap ثم catch-up.
- reconnect وإعادة الاشتراك.
- تغير token وإعادة الاتصال.
- component remount وتنظيف listeners.
- تزامن تسجيل الخروج بين tabs.
- دمج invalidations المتقاربة.
- منع retries لأخطاء business وconflict.
- فشل التحميل والطباعة والتأكيد وطلب السبب.
- شاشات الهاتف واتجاه RTL وأهداف لمس مناسبة.

## التحقق الآلي

- اختبارات المكونات المشتركة تغطي حالات العرض، pagination، السبب، منع التكرار، conflict، money، quantity، والتاريخ.
- اختبارات Realtime تغطي duplicate/stale/gap، الاشتراك، catch-up، التخلص من listeners، query mapping، batching، ورؤوس الوصول العامة.
- اختبارات سياسة React Query تغطي أكواد business وأخطاء الخادم المؤقتة.
- لا يوجد Chromium أو Playwright ضمن التنفيذ.
- النتيجة النهائية: 10 ملفات اختبار و46 اختبارًا ناجحًا، وESLint ناجح، وproduction build ناجح.
- فحص baseline الشامل ما زال يفشل بسبب 99 مخالفة قديمة موزعة على الموديولات التي لم تصل مراحل ترحيلها بعد. لم تزد endpoint literals أو mock imports أو numeric IDs في هذه المرحلة، وانخفضت مواضع localStorage من 46 إلى 34.
